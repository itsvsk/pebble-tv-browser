# v0.1.1 release review

The release combines browser quality-of-life controls with streaming layout, fullscreen and nested scrolling fixes. The [physical TV report](tv-qol-2026-10-28.md) records the earlier Android 14 device smoke test; subsequent review fixes use emulator regressions and the API 24/34 CI matrix.

## Review changes

- Codex's GitHub review identified a DOM fallback-mute bypass when a playing site changes `muted` without a new `play` event. A capturing `volumechange` listener now reuses the current policy, with conditional writes that avoid recursion. Explicit Unmute remains covered.
- Independent review identified a Desktop-to-Mobile user-agent change on download Retry. New records retain their initiating user agent; Retry uses it with fresh cookies. Nullable schema 3 metadata and explicit upgrades from schema 1 and schema 2 preserve existing data and failure reasons. Legacy records use the current default when their original agent is unknown.
- Independent review identified pointer reactivation over a page-error panel. Down from the address controls now closes the editor and focuses Retry, and cursor reactivation is suppressed while the error remains. Native key tests cover editor-to-Retry and activation.

Each behavioral defect was demonstrated by a failing regression before its fix. The review also inverted the closed-tab privacy guard temporarily: both closed-tab behavior tests failed, and the original source was restored.

## CI compatibility and fixture corrections

The initial hosted run exposed inverted horizontal scrolling with older WebViews. [Chromium's upstream change](https://github.com/chromium/chromium/commit/5d4f3a66a233cbc230db7595c118ad65d00eca1f) corrected Android horizontal wheel conversion in Chromium 145. Pebble now normalizes the synthesized horizontal axis using the underlying default engine agent, independently of per-site identity. Tests cover older, fixed and unidentified providers. Vertical scrolling is unchanged.

API 24 logs identified WebView 53.0.2785.124 and repeated system `audioserver`/FastMixer crashes during media tests. The existing CI jobs now use a PulseAudio null sink instead of disabled audio; progression and pause assertions remain enabled. Android emulator sources document its [PulseAudio backend](https://android.googlesource.com/platform/external/qemu/+/refs/heads/emu-master-dev/audio/paaudio.c), and the [emulator documentation](https://developer.android.com/studio/run/emulator-commandline) explains audio options. Hosted execution must confirm that the audio-service crashes disappear.

The first null-sink run could not initialize the emulator's `pa` driver. CI now supplies the backend's explicit `QEMU_PA_SERVER` Unix socket and named sink/source, verifies socket connectivity, and preserves all media assertions. The API 34 hosted run passed all 42 tests and database checks before the subsequent provisional-navigation regression additions.

Continued API 24 network recovery investigation also reproduced a production guard defect. [WebView.getUrl()](https://developer.android.com/reference/android/webkit/WebView#getUrl()) may still identify the previously committed page after a new load starts. Document state now accepts the started URL while that native snapshot remains unchanged, preserves native authority when it advances, and rejects previous-page failures and stale redirect finishes. Five pure state tests and two additional app regressions cover these transitions; the new regressions failed before the fix.

The fullscreen fixture now explicitly sizes its button to the viewport for old CSS implementations. Network recovery uses a refused HTTPS loopback connection instead of waiting on external DNS. Synthetic failure callbacks and Retry assertions use the provider's native document URL, since `loadDataWithBaseURL(about:blank, …)` can expose a `data:` native URL. Main-frame, stale-document, authentication and subresource assertions remain intact. Remote recovery input is tested after the OS keyboard's input stage; keyboard navigation itself is left to the IME.

## Verification gates

Local release validation passed: 37 unit tests, Android lint, optimized release compilation, the complete 44-case API 34 app suite, and three database checks covering current-schema reopen and both upgrade paths. The PR additionally requires hosted API 24/34 checks. A tag must not be published until the reviewed head passes them.

The existing release workflow checks the exact tag, reruns CI, signs with the established key, verifies the public certificate and package version, smoke-tests the signed APK, and publishes its checksum and mapping alongside the APK. No tests or release-signing checks were disabled, and no additional CI job or production dependency was added.

DRM/subscription services and the documented Vimeo compatibility failure remain outside the verified support claims. A background-playback opt-in cannot override a website or OS restriction.
